# Evidence-backed resume tailoring

- Read latest official JD, master resume and Story Bank before proposing changes. The user's links are bound at setup; use only those user-supplied, authorized resources.
- Build a private requirement-to-evidence table: direct evidence, transferable, unsupported and unknown. Ask narrowly about material gaps; do not invent deep experience from keyword similarity.
- Wait for human selection before tailoring, and human approval before substantial bullet rewrites, deletions, or changing the canonical Story Bank. For small supported keyword additions, follow user's explicitly stated edit boundaries.
- Never overwrite base/master resume. Create one independent Google Doc copy in the configured output folder per selected role. Preserve original formatting, fonts, margins, line spacing, titles and detailed achievements unless user approves a rewrite.
- Use original project scope and truthful quantitative evidence; don't add fake skills, leadership, ML model ownership or outcome percentages.
- Export and render PDF with available authorized tools; visually verify exactly one page and no cut-off. If unavailable or a second page appears, report it honestly and seek revision scope rather than deleting accomplishments without permission.
- Deliver new Doc URL, any PDF link/export, concise change log, supported/unsupported keyword gap list and verified page count. Never submit the application.
